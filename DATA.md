# Data Requirements

This release does not redistribute the original Porto or GeoLife trajectory
files. Synthetic and Grid-Network data are generated by the repository code.
The real-data adapters construct controlled anomaly benchmarks from external
normal trajectory pools.

## Porto-derived input

The source is the ECML/PKDD 2015 Porto Taxi Trajectory Prediction dataset
distributed through the Kaggle competition "Taxi Trajectory Prediction (I)".
Download its `train.csv` from the official competition data page. The raw file
must contain `TAXI_ID`, `TRIP_ID`, `TIMESTAMP`, and JSON `POLYLINE` columns.

Convert the raw file deterministically in source-row order:

```powershell
python src/prepare_porto_od_csv.py --input D:\data\porto_train.csv --output D:\data\porto_trajectories_all.csv
```

The converted CSV schema is:

```text
taxi_id,trajectory_id,timestamp,source_point,target_point
20000589,1372636858620000589,2013-07-01 00:00:58,POINT(-8.618643 41.141412),POINT(-8.630838 41.154489)
```

Coordinates are WGS84 longitude/latitude. Invalid polylines and trajectories
with fewer than two points are skipped; the first and last valid points become
the OD pair. The exact intermediate used for the reported results has 1,674,160
data rows (plus one header), size 173,370,107 bytes, and SHA-256
`4180A908E7857E57A3E49A7C18835B306B256275D0910794F298EC339D2D2F25`.

Set either:

```powershell
$env:EWGB_PORTO_CSV = 'D:\data\porto_trajectories_all.csv'
```

or set a data root containing the expected relative file:

```powershell
$env:EWGB_DATA_ROOT = 'D:\data'
```

The adapter also checks `porto_trajectories_all.csv` below that root and the
candidate locations recorded in `configs/revision_protocol_latest.json`.

## GeoLife input

Download Microsoft Research GeoLife GPS Trajectories 1.3 from its official
dataset page. Provide the unmodified archive as a ZIP containing `.plt`
trajectory files:

```powershell
$env:EWGB_GEOLIFE_ZIP = 'D:\data\geolife.zip'
```

Alternatively place the archive under the relative layout described in the
revision protocol and set `EWGB_DATA_ROOT`. The preparation script imports
`prepare_geolife_context` and `geolife_dataset` from
`src/run_cross_dataset_ablation.py`.

The archive used for the reported results contains 18,670 `.plt` files, has
size 313,164,406 bytes, and SHA-256
`1107C5AC064D0A23C8D021A8736A77E53ABC75B227062E6260342C6A8D86BDB6`.

Each cache stores the predefined trajectories and labels used for evaluation. Its
cached `trajectory_shape` matrix is used only in the shared 34-dimensional
generic-baseline representation. EWGB-TAD does not consume that matrix: it
fits trajectory-shape PCA directly from the cached trajectories for every
main, ablation, sensitivity, stability, timing, and figure execution path.

The exact 30 dataset-seed blocks used by the released summary are listed in
`results/phase4/metadata/dataset_seed_manifest_latest.csv` and
`dataset_seed_manifest_latest.json`. The manifest records the expected counts,
trajectory shape, anomaly construction, and SHA-256 digest of each local cache;
the caches themselves are intentionally excluded from this public package.
Exact label-free inner train/validation indices for LSTM-AE, USAD, and LM-TAD
are included separately in
`results/phase4/protocol/unlabeled_inner_splits.npz`, with counts and hashes in
`unlabeled_inner_split_manifest.json`.

## Data construction and labels

The primary protocol uses 10% nominal contamination with integer allocation.
It injects four anomaly types in a fixed order: detour, loop, speed, and route
deviation. Because allocation is integer-valued, the realized contamination
is recorded in the manifest and metadata. Porto-derived and GeoLife labels
therefore identify controlled injected anomalies; they do not claim natural
anomaly annotations.

The complete injection parameters, counts, seeds, and source functions are in
`configs/anomaly_injection_manifest_latest.json`. Do not place private raw data
inside the repository before publishing it.
